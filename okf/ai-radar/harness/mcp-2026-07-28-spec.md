# Summary

The MCP spec dated 2026-07-28 moves the protocol core from
bidirectional/stateful to request/response, enabling serverless/edge MCP
servers. Adds a versioned extensions framework (MCP Apps, and a Tasks
extension where `tools/call` can return a task handle driven by
`tasks/get/update/cancel`), plus OAuth2/OIDC alignment for enterprise
identity.

# Why this is in the radar

Foundational protocol change underlying every MCP server this setup connects
to (GitHub MCP, others). Worth tracking for when/whether Claude Code's own
MCP client adopts the new extensions (Tasks in particular would matter for
long-running tool calls).

# Update (2026-09-08 scan): roadmap published

The MCP steering group published its next roadmap on 2026-08-22 (just
before the last scan's window, evidently missed then): five priorities,
each with assigned Core Maintainers/working groups — (1) agentic messaging
beyond request-response (maturing the Tasks extension, server-initiated
events/webhooks); (2) extending stateless HTTP transport to more deployment
modes including local stdio; (3) standardized agent identity via DPoP and
Workload Identity Federation instead of raw API keys; (4) standardized
tool-result handling and progressive tool discovery for large tool
catalogs; (5) SDK ergonomics/conformance testing. Verified via the official
modelcontextprotocol.io blog. The agent-identity and progressive-tool-
discovery priorities are directly relevant to how this repo's own MCP
integrations will need to evolve.
