# design-full — customization layer (P6): avatars, effects, design-config

## design-config.json schema (written to docs/design/design-config.json)

Synthetic example — field names are the contract for design_tab_scaffold.py:

```json
{
  "version": 1,
  "theme": {"modes": ["light", "dark", "auto"], "default": "auto"},
  "density": {"options": ["compact", "regular", "roomy"], "default": "regular"},
  "accent": {"options": ["#2fa36b", "#3b6fd6", "#d65a3b"], "default": "#2fa36b"},
  "avatars": {
    "enabled": true,
    "sets": ["flat-geometric", "hand-drawn", "pixel"],
    "default": "flat-geometric",
    "params": {"hair": 6, "skin": 8, "accessory": 5, "palette": "from accent"}
  },
  "effects": [
    {"id": "peel-menu", "label": "Peel menu", "enabled": false,
     "reduced_motion_behavior": "disable", "fallback": "standard dropdown",
     "source": "linked: canvasui.dev/docs/components/peel"},
    {"id": "droplets", "label": "Droplets", "enabled": false,
     "reduced_motion_behavior": "disable", "fallback": "none",
     "source": "linked: canvasui.dev/docs/components/droplets"},
    {"id": "scroll-narrative", "label": "Scroll story", "enabled": false,
     "reduced_motion_behavior": "static-sections", "fallback": "static"}
  ]
}
```

Rules: every effect entry MUST have `reduced_motion_behavior` and
`fallback`. Defaults conservative: effects ship OFF unless the intake said
"playful" appetite AND the focus gate favored them.

## Optional effects registry notes

- **peel-menu / droplets (CanvasUI)**: advanced WebGL components (GLSL
  shaders, experimental canvas attributes). LINK, do not vendor — license
  unverified; if the user later wants them vendored, run /skillspector-gate
  first. Both are GPU-heavy: gate behind capability check
  (WebGL2 available + not reduced-motion + not saveData) and always ship
  the fallback (peel -> standard dropdown; droplets -> off). Screen-reader
  note: canvas effects are aria-hidden decoration, never interactive-only
  paths.
- **scroll-narrative**: CSS/JS scroll-scrub pattern per scroll-motion.md;
  degrade to static sections.
- Any effect the user asks for gets an entry with the same three fields;
  effects without an accessible fallback are rejected (AJ51).

## Avatar specification (youth-oriented)

3 style sets, each fitting the locked brand direction, e.g.:
- flat-geometric: simple shapes, brand palette, bold silhouettes.
- hand-drawn: zine/marker line quality, imperfect edges.
- pixel: 8/16-bit (route hermes-pixel-art when installed).

Per set: 4-6 sample avatars as SVG (preferred; parameterizable) in
`docs/design/proposals/avatars/<style>/avatar-01.svg...`. Each set documents
its customization params (hair/skin/accessory/color counts) in a README.md
so the Design tab picker and future generation are consistent. SVGs must be
self-contained (no external refs), ASCII-safe ids, and readable at 32px.

Video avatars (optional): heygen skill — `/v3/avatars` for avatar videos;
HyperFrames `/v3/hyperframes/renders` can render an HTML avatar card to MP4
for animated previews. Only with HEYGEN_API_KEY and explicit user opt-in;
never a pipeline dependency.
